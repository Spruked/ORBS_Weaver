# Orbot Agent Instructions

Orbot is provider-agnostic.

## Core rules

- Do not hardwire Orbot to Grok, xAI, OpenAI, Anthropic, Google, or any other model provider.
- Provider-specific integrations must live behind adapters/interfaces.
- TanStack Start framework requirements may remain framework-specific.
- AI-provider architecture must remain interchangeable.
- Preserve TTI = True Technical Intelligence.
- Preserve RAL = Real-Time Agency Loop.
- Preserve Core-4 architecture: Kant, Locke, Hume, Spinoza.
- Deterministic safety/admission logic must never depend on model output alone.
- Do not bypass World State validation, execution permits, authority checks, or correspondence checks.
- No scripted task choreography. Intent may be autonomous; execution remains deterministically bounded.
- Do not commit secrets, API keys, tokens, credentials, or local environment files.
- Prefer local/provider-neutral interfaces wherever possible.

## Current framework

- TanStack Start
- `src/router.tsx` exports named `getRouter()`
- File-based routes live in `src/routes/`
- `src/routes/__root.tsx` is the document shell
- `routeTree.gen.ts` is generated by TanStack tooling

## Provider architecture

Use interfaces such as:

- IntelligenceProvider
- SpeechProvider
- ToolProvider
- AuthProvider

Implementations may include local models or external providers, but application logic must not depend directly on one provider.

## Build discipline

Before changing architecture:
1. Inspect existing dependencies.
2. Preserve working framework conventions.
3. Keep provider-neutral contracts separate from provider adapters.
4. Run typecheck/build after structural changes.
5. Do not commit until the build is clean unless explicitly instructed otherwise.
